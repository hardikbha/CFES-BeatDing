## Exact gradient defect

Its SHA256 is `bef29fa69e46c729dc679356d0ac3904ebac6da4c00180350daf282fe94599db`. The input group tensors are already detached. GeomLoss0.3.1 can re-enable global grad mode internally, so total CE loss can backpropagate while the fairness term stays detached. A different dependency can instead fail backward entirely. The fresh fixture confirms the detached-fairness behavior; it does not establish what the paper authors trained. No gradient repair is present in the archived file. Simply removing no_grad would still align mixed-class logit vectors rather than Eq.6's class-conditioned probability distributions.

## Ding-CC-OT-r1: explicit new adaptation, not a rewritten archive

[Exact configuration](DING_CC_OT_CONFIG.json). Tested loss kernel `corrected_ding_cc_ot` in [ces_fl_cdf_objectives.py](../../src/ces_fl_cdf_objectives.py) uses scalar fake logit `z_fake−z_real`, equivalent to softmax fake probability. For each y∈{0,1}, align each group's empirical fake-probability distribution with pooled same-class probabilities, then sum the two class terms and average groups. Training must have gradients enabled; missing class×group support rejects. CPU/CUDA tests show nonzero fairness-only gradients, lambda-dependent updates, independent real/fake conditioning, score-adapter equivalence, and finite loss for constant scores.

Regularized OT uses pinned GeomLoss0.3.1,p=2,epsilon5e-4,blur=sqrt(epsilon)=0.0223606798,debias=False,tensorized,diameter1.0 for probabilities bounded[0,1]. The native API blur5e-4 corresponds to epsilon2.5e-7 for p2, and its default debias=True is a Sinkhorn divergence; those are **intentional disclosed differences**, not a claim of exact paper reproduction. GeomLoss p2 uses cost0.5|x−y|²; the paper describes squared distance. KDE is not implemented. Constant auto-diameter caused an executed failure before setting the fixed valid support diameter; failures are preserved. [Paper Eq.4–6](https://arxiv.org/html/2511.10150v5), [official API](https://www.kernel-operations.io/geomloss/api/pytorch-api.html).

The proposed corrected adaptation optimizes only the declared classifier, freezes BN buffers, honors the outer seed and requires an actual TRAIN-ranked SFD mask receipt. Classification/SFD/adaptation and their optimizer exposure are reported separately; it must not borrow a CES pretrained checkpoint and call it Ding classification. A minimal no_grad-only repair, if ever run, is another diagnostic row, not this adaptation.

Equal epoch/step budgets do not remove the difference between full CES encoder fine-tuning and head-only GDA. Report stage-specific trainable counts, image exposure and optimization choices. Response-versus-score isolates our proposed method within the identical CES system; a system-level advantage over corrected Ding would not, by itself, establish that our fairness loss is superior under matched trainable capacity. That stronger loss-comparison claim would require a separately specified capacity-matched OT control.
