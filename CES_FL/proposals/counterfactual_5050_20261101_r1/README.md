# Full-coverage counterfactual CES-FL: 50 + 50 epochs

The user requested restoration of the original demographic-counterfactual mechanism, a 50-epoch pretraining plus 50-epoch downstream budget, an explanation before publication, tested code and a GPU-node prompt. The user clarified that “E-box” meant epochs. This package implements that request; it does not modify the evidence-output architecture or any completed result. It is separate from the newer joint-contribution-MMD proposal.

Standalone executable: `CES_FL/src/ces_fl_counterfactual_5050.py`. Exact unbound configuration: `protocol_config.json`. No project imports, downloads or implicit cluster launch. The source embeds the existing CES-FL Xception architecture and requires Python >=3.10, PyTorch, NumPy, Pillow and scikit-learn. Generation additionally needs an existing compatible diffusers/transformers/accelerate installation and the pinned-path local Qwen-Image-Edit-2511 snapshot. Local synthetic tests do not certify real Qwen generation or the cluster software environment.

## Intended mechanism and the actual correction

The old upgrade paired ordinary training batches with repeated draws from six separate anchors. This implementation has no separate pair pool. Every TRAIN original appears exactly once each epoch, in a seeded shuffled order. Each original in the counterfactual arm is paired with its own reviewed variant. A source-specific seeded offset rotates age, gender presentation and skin tone over epochs. Where both directions are approved, the direction cycles on successive visits to that attribute. Every original visits all three attributes in each three-epoch cycle and both available directions in each six-epoch cycle. With 50 epochs each attribute receives 16 or 17 visits per source. The code logs source coverage, actual pair counts, attribute/direction exposures and label×group×attribute exposures.

Generation occurs once, offline, from originals; it does not run inside each training step and does not generate from another edit. Per-source candidates are younger adult, older, more feminine presentation, more masculine presentation, lighter skin and darker skin, plus a no-change editor control. Prompt intent is to preserve identity, pose, background, texture and existing manipulation artifacts. These prompts are requests, not evidence that preservation succeeded. A geometric resize-only diagnostic control is also saved; it is explicitly not a latent reconstruction or complete editor control.

Generation plans include every TRAIN row with source-image SHA256 and contributor provenance. Each condition consumes a fresh copy of that original with a deterministic per-source seed shared across conditions. Outputs are canonicalized to original dimensions; native output dimensions and requested geometry are recorded. Sources are sharded deterministically and locked against simultaneous writers. Existing outputs are hash-verified on resume. Unrecorded partial output or stale locks are preserved for explicit recovery. Generated candidates are never automatically approved. No validation/test original is edited or used as a training counterfactual.

For the current 76,139-original TRAIN set, six candidates plus one generated no-change control mean **532,973 diffusion outputs**, plus 76,139 geometric controls. Storage and compute must be measured with the actual small GPU generation pilot; no completion time is asserted. Native high-resolution outputs are not retained by default; canonical PNGs and provenance records are retained. The model snapshot path is pinned but its binary files are not independently hashed by this script; record the cluster snapshot provenance separately.

Every original must have at least one approved variant for each of age, gender presentation and skin tone, and an approved no-change control. Not every direction must pass: a rejected or ineffective direction must not be silently accepted. Review records require a named reviewer, evidence reference, correct source/candidate association, identity preservation, a valid target edit (or unchanged appearance for no-change), preserved forensic label/evidence, and preserved unrelated details. A visual check alone does not prove forensic validity. Real labels/provenance are never fabricated. If any source lacks an attribute/control, the coverage audit fails; it never substitutes another person's edit, silently drops a TRAIN row or falls back to the old six-person pool. Failed sources need re-generation/review under a separately recorded correction; keep prior records. Production binding requires full coverage and completed verified pretraining.

## Matched 50+50 experiment

| Stage/arm | Epochs | Data and objective | Encoder/BatchNorm |
|---|---:|---|---|
| P | 50 | Original TRAIN only; group-weighted BCE | Full encoder/head training; BN running statistics update |
| B | 50 | Same originals; group-weighted BCE | Full encoder/head training; BN running statistics frozen |
| N | 50 | Same originals plus their own no-change controls; BCE + score consistency | Same as B |
| C | 50 | Same originals plus their own reviewed demographic edits; BCE + score consistency | Same as B |

P is run once and shared. This is **200 sequential training epochs across the controlled study**, not 200 per model: 50 shared pretraining + three 50-epoch downstream comparisons. Each B/N/C path has a 50+50 training budget. Pretraining completes all 50 epochs, then its validation-selected encoder is imported, with identical fresh heads/gates/fusion for B/N/C. The selected encoder may originate from an earlier epoch; this is disclosed validation selection, not a claim that every selected model completed 100 updates through its ancestral weights.

The complete model is the existing global MLP + shared patch MLP + sigmoid image/patch gates + positive fusion. All 21,594,159 parameters train in P and B/N/C. No frozen/partial-encoder bottleneck remains in this particular full-finetuning experiment. Optimizer is AdamW; head LR 0.001, P encoder LR 0.0001, downstream encoder LR 0.00001, weight decay 0.0001; batch size 16; seed/head seed17. A singleton final minibatch is merged into the previous minibatch so P can update BN while retaining every source exactly once.

Original sampling changes deliberately from weighted replacement to a full shuffled pass, ensuring actual coverage each epoch. To retain balanced class/group influence, each source receives fixed weight `N / (number_of_label_group_cells * cell_count)`, using the TRAIN `ids8` field. The loss is a mean of those weighted sample losses, with no per-minibatch weight renormalization. All arms share that rule and data order. Counterfactual/no-change arms have two forwards per original, BCE has one; optimizer-step budget is matched, FLOPs are not identical. Full-support group metadata is required and unknown groups are rejected.

For original logit z and its own edited/control logit z_cf, the paired term is `|asinh(z) - asinh(z_cf)|`, weighted by the same fixed source weight and lambda_d=1. The classifier BCE is applied only to originals. This is score invariance, not a guarantee of invariant evidence maps. The training intervention tests the premise that validated demographic edits should not change the forgery decision. Joint MMD, Group-DRO, forensic-sensitivity margins and spatial map consistency are not silently added to this restored trial.

## Selection, checkpoints and outputs

All runs select by validation AUC only, preserving the established selection convention. Each selected checkpoint stores the conservative threshold calibrated on validation real images to a 10% empirical FPR budget. Test data never selects epochs, hyperparameters or thresholds. Training records all validation subgroup metrics, but does not change selection to whichever fairness metric looks best. Selected checkpoints are independently reloaded and validation metrics replayed before `RUN_VERIFIED.json` and `DONE` indicate success. Epoch-boundary resume requires identical source/config/stage and consistent history/checkpoints; completed outputs cannot be overwritten.

The existing output decomposition remains `z = global_contribution + mean(local_map) + fusion_bias`. Private export saves the signed local contribution map and its accompanying global/bias terms, plus a sigmoid score and the decision at the frozen validation threshold. A sigmoid score is not a calibrated probability, gates are learned weights, and local maps are not validated forgery masks. Export checks the additive decomposition.

No new result or improvement over Ding is claimed. Matching a 50+50 schedule does not match Ding's optimizer, batch size, trainable stages, annotations or threshold protocol. This is a single-seed controlled trial. The historical CESel-MA gate remains unchanged. Report the original, no-change and demographic arms separately; no-change controls are necessary to interpret generic editor changes. Do not decide whether to keep an arm based on test scores.

## Launch dependencies

Use `GPU_OPERATOR_PROMPT.txt`. `plan` validates immutable cluster manifests, original image hashes and local ImageNet weight hash. `generate --max-sources 2` measures real generation on a small class-balanced pilot when both classes are present; review it before the remaining workload. Re-running generation with no limit continues the full inventory. `review-template` writes only pending decisions. `audit-coverage` is a separate read-only validity/coverage check. `bind` creates an exact new config and hashed pair bank only after coverage passes and P is complete; no future checkpoint hash is invented in the static config. Training never runs Qwen or invents approval labels.

Real generation, quality review and the 50+50 cluster runs are pending. The local `smoke` command exercises temporary synthetic generation stubs, smaller hidden layers and reduced 1+2 fixture epochs, plus the full-width 224px architecture; fixture plans/checkpoints are explicitly rejected by production commands. A synthetic PASS is not a real generator, validity, GPU-performance or fairness PASS. The GPU operator must repeat CUDA smoke and the configured real-data dry run on an allocated device before launching full training. The operator must publish the bound config/hash and actual launch evidence in a new dated request/result record, without publishing face images, binary weights or private review details.
