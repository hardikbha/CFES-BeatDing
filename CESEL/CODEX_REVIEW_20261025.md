# CESel code review — 25 October 2026

## Verdict

**Changes are needed before relying on concurrent recovery, automatic promotion decisions, or all reported evaluation numbers.** The core CES objectives passed the supplied smoke suite (**17/17, ALL_PASS**, including real CLIP on CPU) and additional edge checks. The review found one blocker, seven major findings, and three minor findings. Passing the existing suite does not cover these orchestration and evaluation failures.

Reviewed the three requested design documents and all **80 files** under `cfes/`, `scripts/`, `run/`, `configs/`, and `tests/`. [File inventory and SHA-256 hashes](review_scratch/reviewed_files.sha256) enumerate the coverage. Amendments 1–2 take precedence over the older README descriptions of class-only replacement and global cue validation. Findings below distinguish executable reproductions from static inspection.

The code under review was not edited. New files are confined to this snapshot: this report and `review_scratch/`. No GPU execution, PBS submission, package installation, or long training was performed. Python commands used `/home/sachin.chaudhary/.conda/envs/pulid/bin/python`, `CUDA_VISIBLE_DEVICES=""`, disabled bytecode writes, and a snapshot-local temporary directory. The original runners were never executed; the lock test uses an extracted copy of their function with a scheduling barrier.

## Findings

Line references refer to the snapshot, not proposed fixes. Severity reflects the affected path; FF2-only problems do not imply the currently running FF++ arms encountered them.

| ID | Severity | File:line | Problem and concrete failure scenario | Suggested fix / evidence |
|---|---|---|---|---|
| F1 | **Blocker** | `run/cesel_run.sh:44–56` | **Stale RUNLOCK recovery is not an exclusive acquisition.** After `mkdir` fails, any runner observing a stale heartbeat proceeds to overwrite `owner`; it never atomically competes for ownership again. Two PBS runners can both observe the same stale lock and train/resume into the same output directory. Both EXIT traps also unconditionally delete the lock, including a successor's lock. Shared `last.pt.tmp` / `best.pt.tmp` then make checkpoint corruption or replacement possible. | Serialize acquisition and stale recovery with a shared-filesystem-supported lock, use an ownership token, and remove only a lock still owned by that token. A live owner must not be fenced out solely by an old heartbeat without a safe lease/fencing protocol. **Reproduced:** both contenders printed `ACQUIRED` for the same lock. A fresh-lock contender correctly exited 4. |
| F2 | **Major** | `scripts/cesel_report.py:98–113` | **Promotion does not enforce all pre-registered term-retention gates.** `dropped_terms` contains only negative-control drops; failed single-term arms are omitted. With B0-continued=90, +sens=89, Full=95 and controls far from Full, Full is promoted despite containing the failed sens term. Separately, `complete` ignores an unavailable reference spread: pending control decisions still allow promotion. | Add failed single-term retention tests to the excluded-term set, and require every relevant gate to be resolved before promotion. Freeze the declared spread/reference provenance or fail closed if it is unavailable. **Both cases reproduced** with local TRAINED fixtures. |
| F3 | **Major** | `scripts/train.py:101–105,124`; used by `scripts/train_ces.py:114,169` | **Checkpoint-selection AUC ignores `eval.rank_metrics`.** Validation evaluates sigmoid probabilities even when the config requests rank metrics. Float64 sigmoid ties positive logits around 37 and above. Thus a saturated model can receive an incorrect AUC and a different `val_oppoint` selection value, while test reporting uses unsaturated ranks. | Compute validation AUC and group AUC from logits or `rank_prob(z)` when enabled. Keep operating-point decisions on the logit scale. **Reproduced through `validate()` with mocked predictions:** logits `[-50,40,41,42]` per group give reported AUC **75%**, versus true logit AUC **100%**. This demonstrates the failure, not its occurrence in a particular CESel run. |
| F4 | **Major** | `scripts/evaluate_ces.py:82,101,109–110`; `cfes/metrics.py:134–140` | **The validation-TPR threshold changes meaning on each test dataset.** `rank_prob` divides by that dataset's maximum absolute logit. A threshold selected from validation ranks is applied to independently normalized test ranks. Test outliers therefore change the decisions of other test images. This affects `acc@val`, `fpr@val`, `tpr@val`, and `fair@val`; raw threshold 0.5 and the separate A1 path are unaffected. | Select/store the threshold in logit units and apply the same logit threshold everywhere; use ranks only for AUC. **Reproduced:** validation `[-2,-1,1,2]` yields rank threshold 0.666667; test `[-100,-1,1,2]` predicts all real instead of the correct `[real,real,fake,fake]` at the fixed logit threshold 1. |
| F5 | **Major** | `configs/cfesd_ff2_public.yaml:26` | **The public-only baseline initializes from FF2-FULL training.** The default checkpoint is `runs_ff2full/clip_s7_p1/last.pt`, which the config itself documents as trained with excluded data including RFW. Changing phase-2 CSVs does not remove that training exposure. A run using this config unchanged cannot satisfy the pre-registration's public-TRAIN-only requirement. | Require a phase-1 checkpoint trained on frozen public TRAIN, with provenance checked, before making this baseline runnable as a public-only experiment. The warning in the header acknowledges the problem but does not enforce the requirement. **Static/config evidence**; no claim that this config has already been launched. |
| F6 | **Major** | `configs/cfesd_ff2_public.yaml:77–116,138–140` | **The config named CFES-D is a different recipe.** It contains no `loss.risk`, so the shared engine never activates D's real-group-risk term. It also selects `val_inter_es_auc`, whereas the CESel screen uses Amendment-9 `val_oppoint`. Launching the named baseline as supplied therefore compares against a non-D objective and a different checkpoint selector. | Build an explicit public CFES-D config with the declared D risk weight/settings and the matched selection protocol; keep a separately named B recipe if needed. **Static/config evidence:** `cfes.engine.active_terms` only enables risk when its weight exists and is positive; the local README and `configs/arms/B0_cfesD.yaml` explicitly include risk for D. |
| F7 | **Major** | `scripts/fair_a1.py:15,73–76`; `scripts/ces_posteval.py:68` | **FF2 test results are silently omitted from A1 output.** The caller passes all configured test sets, but `a1_for` iterates a hard-coded four-dataset FF++ list. For an FF2-public run, `a1.json["test"]` lacks `ff2_test` even though its scores exist. Raw/calibrated reference sections do include it, which can conceal the omission. | Pass dataset schemes to `a1_for` and iterate the supplied test sets, including FF2. **Reproduced:** a valid A1 threshold is found, but a supplied `ff2_test` entry disappears. |
| F8 | **Major** | `cfes/data.py:46–50,77–80`; `scripts/evaluate_ces.py:104` | **Non-video image IDs are incorrectly treated as frame suffixes in leak-free filtering.** `cluster_key` strips every trailing numeric suffix, not just FF++ frame indices. FF2 PixArt images without person IDs collapse to six demographic-cell names, e.g. `pixart_Asian_Female`. Independent train/test images in those cells are then treated as the same video. | Use dataset-aware cluster keys: explicit person/video provenance where available, full image identity otherwise. Strip frame indices only for recognized video naming schemes. **Observed on configured public manifests:** the leak-free-video filter drops **1,274 PixArt test rows**, with **zero exact train-path matches**. This is false video-overlap filtering, not evidence that those generated images share an identity. |
| F9 | **Minor** | `scripts/ces_posteval.py:126–133` | **Full cue deletion ranks floating-point summation error.** Saved `score` is a float32 sum; post-evaluation subtracts a float64 sum of saved cue contributions. After deleting all four cues, the mathematically constant score retains image-dependent rounding residuals. AUC is sensitive to their ordering regardless of their tiny magnitude. | Reconstruct each intervened score from retained cue terms plus replacement constants and head bias. For full deletion, explicitly construct the constant `b + sum(beta0)`. **Reproduced:** residuals `[-2.235e-8,-2.235e-8,0,0]` give AUC **100%**, whereas the exact constant gives **50%**. |
| F10 | **Minor** | `scripts/cesel_report.py:195–199`; `scripts/cesel_pipeline.py:219–226` | **Both runners can race when publishing the shared report.** They use the same Markdown `.tmp` filename and write JSON directly. If A replaces the temporary Markdown after B has written it, B's subsequent replace fails; JSON can be read partially or be overwritten by an older partial report. A final report failure makes an otherwise completed pipeline exit 6. | Serialize report publication, use unique temporary files plus atomic replace for both formats, and prevent an older partial report from replacing a completed result. **Static concurrency finding**; the full pipeline was not executed. |
| F11 | **Minor** | `run/cesel_run.sh:44–56,64,77,83` | **Output paths are word-split and glob-expanded.** `CESEL_OUT` is an advertised override, but `mkdir $L`, `take_lock $out`, `--out $out`, and the expanded EXIT trap are unquoted. A scratch/output root containing spaces fails to identify one output/lock path, and cleanup can target multiple words. The fixed production path has no spaces. | Quote scalar paths everywhere, use arrays for argument lists, and implement cleanup as a function using the quoted lock path and ownership token. **Static argument-expansion finding**, not a style complaint. |

## Checks without a confirmed core-loss defect

- Cue ordering, additive head equations, replacement signs, detached references, the pooled floor stop-gradient, same-label/different-group donor selection, probe preference comparison, warm-up gating and per-family target indexing agree with the implemented specification. Existing tests exercise closed-form versus explicit head replacement, gradients, planted demographic subspaces and independent control RNG streams.
- The current configs use `kappa=1`, positive geometry/window settings and nonempty cue supports. No NaN/division-by-zero failure was found for the exercised normal settings or empty floor groups. Invalid arbitrary overrides such as zero kappa are not covered by this conclusion.
- Inference receives only images. Demographic labels are used by training/state, validation selection, and explicitly labeled post-hoc analyses, not by `CESDetector.forward` or its inference score. Test scores are not inputs to the training selector or cue-validation pass.
- CES pairs are filtered to both endpoints being in TRAIN. The inspected real pair tables also have correct endpoint labels. The loader itself does not independently assert endpoint label roles, so this conclusion is about the inspected tables, not every possible CSV.
- The default decoupled RNG path reseeds ordinary/stratified/pair sampling and CES draws by epoch. Checkpoints carry detector optimizer/scheduler/global RNG plus CES state/probe optimizer. New arms intentionally use fresh detector optimizers/schedules with B0's CES state. No additional default-path resume defect was established beyond unsafe concurrent ownership and output publication.
- Both PBS wrappers set the requested per-host GPU allowlists and concurrency limits. The driver checks free memory ≥61,440 MiB and utilization <10%, and atomically creates per-host GPU slot directories. STOP is checked by the driver and at shell entry and intentionally lets existing children finish. These are static checks, not a GPU/PBS validation. GPU availability is sampled before acquisition, not reserved against unrelated processes; the standalone smoke picker checks but does not acquire the driver's GPU lock.

## Limits and unresolved protocol questions

- No GPU/bfloat16 numerical test, VRAM measurement, real PBS/shared-filesystem recovery, scheduler allocation audit, or long training was performed. F1 is a controlled local interleaving of the copied lock function; F10/F11 are static findings. I did not inspect or change the running jobs.
- The supplied trainer smoke tests initialization from B0, **not** `--resume` equivalence of a complete training process. The added round-trip test verifies CES buffers/probe/Adam state only. Full detector optimizer/scheduler/DataLoader equivalence across an interrupted real run remains unverified, especially with `train.decoupled_rng=false` or nondefault augmentation/backends.
- Full image-content/identity deduplication, provenance correctness, generator ancestry and consent/removal lineage were not audited. Zero exact path overlap is not proof of independent validation. The configured FF++ train/validation tables share **163 video cluster keys**, including different frames of `0_youtube_025`; this appears to be an inherited protocol property and is documented in [cluster_overlap.log](review_scratch/cluster_overlap.log), not attributed to a newly introduced CES loss bug. FF2-public's six apparent cluster overlaps were the PixArt naming collision in F8, not established person overlap.
- README/design notes describe a family-conditioned FF++ floor, and the code implements it. The pre-registration's abbreviated phrase “group x class (x family on FF2)” could instead be read as class-only FF++ flooring. Resolve that wording before making a class-only FF++ claim; I have not counted this ambiguity as a proven implementation bug.
- CNN/FS-VFM and optional matched-set paths were read but not executed. There is no validated matched-set fixture supplied for a real experiment. Arbitrary malformed configs, missing classes in entire evaluation datasets, and every nondefault combination were not exhaustively tested.
- The review verifies metric implementations against their local declared equations and an existing A1 reference; it does not independently authenticate the published Ding table values or establish that CESel improves fairness. Bootstrap validity, demographic probe efficacy, intervention faithfulness and promotion outcomes require actual experimental evidence.
